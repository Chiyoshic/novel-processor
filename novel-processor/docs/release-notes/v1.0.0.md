# v1.0.0 · 把喜欢的日轻小说，收进自己的书架

> 首个稳定版本 · 2026

从“把小说抓下来”，到“整理好、读下去，再试着译成中文”，`novel-processor` 迎来了第一个稳定版本。

这次不只是一个采集脚本：书架、阅读器、阅读记录和 AI 翻译流程终于串在了一起。你可以把喜欢的作品收进自己的书库，按自己的习惯阅读，也可以让模型带着角色表和前文，一话一话地翻译。

**这个版本的重点：采集可续、阅读可记，翻译不必每话都从零开始。**

## 主要功能

### 小说采集：先把想看的作品收好

贴上作品地址或输入 ncode，就可以从目录开始整理。想先试读几话，或把整本书保存下来，都可以自己选。

- 支持小説家になろう作品 URL 和作品 ID；
- 抓取目录、章节、话标题、作者、简介、状态、标签、字数和日期；
- 支持分页目录、官方 API 元数据富化和正文解析；
- 支持按话、话号范围、章节缺失内容和全书下载；
- 已经保存的话可以跳过，不用每次从头抓；也能按需覆盖重抓；
- 并发控制、请求间隔、超时和重试一起管理访问节奏；
- 想暂停这次抓取？取消会真正发到服务端，已保存的正文也会留下；
- 目录和正文以可读 JSON 文件保存。

### 书架与作品管理：下载到哪、读到哪，分开看

“下完了”和“读完了”不是一回事。书架把这两种进度分开，找书、续读和整理目录都更直接。

- 支持标题/作者搜索和多维筛选；
- 下载进度与阅读进度独立展示；
- 作品卡片提供开始阅读和继续阅读；
- 目录显示下载、翻译和阅读状态图标；
- 支持展开全部、折叠全部和按已读话临时折叠；
- 支持回收站、恢复、永久删除和从磁盘重建索引。

### 阅读器：让界面退后一点，让故事往前一点

正文不再装进圆角卡片，而是沿着连续书页展开。纸色、字号和留白交给你调整，原文与译文也可以随时切换。

- 原文与译文切换；
- Noto Serif JP / Noto Serif SC 书页式排版；
- 字号、字距、行距、段距、背景和文字颜色调整；
- 原文与译文共用阅读状态；
- 支持人物全名、短名、原名、中文名和别名匹配；
- 人名眼熟却想不起是谁？桌面端悬浮、移动端点击即可查看人物简介，也可以关闭提示；
- 使用语义化文章结构和打印样式，为 Safari 阅读器模式提供内容结构，是否出现入口仍由 Safari 判断。

### 阅读进度：不用再猜上次读到了哪里

原文和译文共用一份记录。红、黄、绿按真实话序排列，哪几话已读、哪几话还没看，一眼就能找到。

- `unread`、`reading`、`read` 三种状态；
- 打开正文自动记录为在读；
- 阅读到底并点击下一话后记录为已读；
- 支持逐话、章节、全书和起止话号范围编辑；
- 书架使用红黄绿状态分布条展示阅读进度；
- SQLite 持久化阅读状态，更新目录和移动回收站不会清除记录。

### 登录与权限：自己的书库，自己保管

目前只服务一个人的阅读习惯，所以没有注册入口，也不绕一大圈账号流程。该有的会话、密码保护和跨域校验仍然保留。

- 单用户登录模式，不开放注册；
- AT / RT 会话机制；
- Access Token 保存在前端内存；
- Refresh Token 使用 HttpOnly Cookie 和轮换机制；
- 密码使用带随机盐的 scrypt 哈希；
- 支持修改密码并撤销所有会话；
- 支持精确 CORS 白名单和跨域部署。

### AI 模型与翻译：不只是把正文发给模型

长篇翻译最怕的，不只是某句话不够自然，还有前后译名对不上、人物口吻变了、前文刚约定的术语又换了写法。

这个版本把翻译做成了一个持续维护材料的流程：**先认识这本书，再带着上下文翻译，最后把新信息补回材料。** 模型也不绑定一家服务，可以按需要配置：

- 支持 OpenAI Responses API 和 Chat Completions API；
- 支持 OpenAI、DeepSeek、OpenCode 等 OpenAI 兼容服务；
- 支持自定义 Base URL、API Key、HTTP headers 和 extra body；
- 支持 `window_tokens`、`input_tokens`、`output_tokens`；
- 支持 OpenAI / DeepSeek 思考等级和 DeepSeek DSML 适配；
- 支持模型配置的新增、读取、修改、删除和连接测试。

#### 先认识这本书：初始化翻译材料

先让模型读一读简介、前言和前若干话，把后续需要反复参考的信息整理出来：

- 中文书名和剧情梗概；
- 角色中文译名、中日别名和身份信息；
- 笔调、叙事视角、对白风格和节奏；
- 关键术语；
- 世界观、称谓规则、翻译规则和待确认事项。

这份材料会存下来，成为后续翻译的共同基线，而不是生成后就散落在聊天记录里。

#### 带着前文往下译：章节翻译

挑好想翻译的话，剩下的按目录顺序串行处理。每一话都能参考最新材料和最近译文，尽量让译名、语气和节奏接得上。

- 支持逐话、多选、范围和最小未译话快捷选择；
- 后端按目录顺序串行翻译；
- 可加载最近已翻译话作为文风和上下文参考；
- 译文追加到原话 JSON 的 `translation` 字段；
- SQLite 记录每话翻译状态、模型、重试次数、源哈希和警告；
- 阅读器可以切换显示原文和译文。

#### 材料也需要整理：增补、去重与压缩

故事越长，角色和设定也越多。翻译时可以补充新信息；材料里有重复项目，或说明越积越长时，再用合并和压缩来整理，而不是一股脑删掉重来。

- 疑似重复检查；
- AI 合并重复角色、术语和规则；
- 按模块压缩总结；
- 预览、基线哈希校验、确认应用和历史恢复；
- 模型输出支持材料字段的 create / update / delete / read；
- 非法修改逐条忽略并记录警告，不使有效译文失败；
- 引用使用 episode ID，不强制校验引用原文。

修改先预览，确认后再应用；有历史版本可恢复，不必把每次整理都当成一次不可撤销的冒险。

#### 等待有反馈，出错有交代

长任务不该只剩一句“正在生成”。现在可以看到模型正在做什么、已经跑了多久、重试了几次，以及失败到底发生在哪个阶段。

- 默认 60 分钟单次生成总时限；
- 默认 180 秒流式首事件/空闲事件时限；
- 持续产生上游事件时不会因固定 180 秒被截断；
- 网络、限流、服务端错误和超时有界重试；
- 默认最多 3 次调用；
- JSON 自动修复后再进行结构和业务校验；
- 流式任务面板展示调用时间、阶段、输出、重试和失败原因；
- 失败时保留已有材料和旧译文。

### 主题与 PWA：换块屏幕，也能接着读

白天看、晚上看，在电脑上整理、在手机上阅读，都沿用同一套书库。也可以把它添加到主屏幕，少开一个浏览器标签页。

- 日间、夜间和跟随系统主题；
- 手机优先响应式界面；
- Apple Touch Icon、PWA、maskable 和 monochrome 图标；
- Service Worker 应用壳缓存和用户确认更新；
- 不缓存 AT/RT、小说正文、SQLite 数据或 AI 流式响应；
- 支持阅读器背景与浏览器状态栏配色同步。

## 数据与存储

内容留在可读的 JSON 里，索引和个人状态交给 SQLite。需要迁移或备份时，不必猜数据藏在哪里：

- `data/novels/`：作品目录和元数据；
- `data/episodes/`：单话正文和译文；
- `data/library.db`：作品索引、账号、模型、翻译材料、翻译状态、阅读记录和回收站；
- `data/audit.log`：管理操作审计日志。

**记得把整个 `data/` 一起备份。** 重建索引只能同步目录和正文索引，不能替你找回账号、模型配置、翻译材料、阅读记录和回收站状态。

## 部署方式

想放在自己的服务器上，或先在本机试一试，都有对应的启动方式：

- Docker Compose 运行后端；
- 前端构建为静态 `dist/`；
- Nginx 提供 SPA History 路由回退；
- API 可通过 Nginx 反向代理并支持流式请求；
- 前后端通过 `VITE_API_BASE` 和 `CORS_ORIGINS` 连接；
- 支持本地源码运行和后端采集 CLI。

## 还有这些边界，先说清楚

第一个稳定版本不是所有愿望的终点。下面这些能力还没接入，或仍受外部服务和系统限制：

- 当前只有小説家になろう适配器；
- 计划中的カクヨム、アルファポリス、ノベルアップ＋、エブリスタ、ハーメルン和ノベマ！尚未接入；
- 当前是单用户系统，不支持注册和多用户数据隔离；
- PWA 不提供完整书库离线阅读；
- Apple 深色和 Liquid Glass 图标效果由系统最终处理，网页不能保证原生 Icon Composer 行为；
- 初始化材料和上下文能帮助统一翻译，但不能保证模型不出错，译文仍需要人工复核；
- 目标站点、模型服务和第三方字体仍受各自服务条款约束。

## 升级说明

准备升级？先给现有书库留一份备份，再更新服务：

1. 等待抓取和 AI 任务结束；
2. 备份整个 `data/` 目录和后端 `.env`；
3. 同时更新前端构建和后端服务；
4. 检查 Nginx 的 SPA 回退、Service Worker 和 manifest；
5. 访问 `/healthz`，登录后检查书架、模型、翻译材料和阅读记录。
