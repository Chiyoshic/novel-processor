# 翻译材料维护

## 已有数据与重复来源

对 `n4703ix-translation-brief.json` 的离线检查发现：18 个角色、68 个术语，紧凑 JSON 为 43,090 UTF-8 字节；角色中 `リアム・ウィルモット` 与 `アデル` 各有两项。描述和章节来源存在差异，不宜直接删除或拼接。

导出文件只有当前结果，不能证明历史上是哪次调用将 update 写成 create。现有增量协议允许 create 新增，因此该错误确实能够造成重复。现在提示词明确要求先匹配已有原名/别名再 update；执行 create 时若发现名称或别名交集，或者完全相同的字符串规则，将忽略该操作并告警，不覆盖已有信息，也不使有效译文失败。疑似同名不同人可以在维护预览中人工检查。

## 使用

翻译流程 → 初始化翻译材料 → 材料维护 → 去重与压缩。

- **AI 合并所选组**：选择疑似重复组，一次调用综合选中组的信息。名称检测只是建议，模型无法确认时允许不合并。
- **AI 检查全部重复**：在选中模块中让 AI 找出包括语义重复在内的项目，只合并确认重复的项。
- **AI 压缩总结**：选择模块或全选，目标为原体积的 80%/60%/40%，仅为软目标；保留实体、固定译名、别名及来源 ID，精简重复说明和剧情流水账。不变小的模块保持原样。
- 展示与翻译任务一致的调用时间、重试、实时流式输出和 JSON 修复状态。生成预览不会直接改变材料，确认应用才写回 SQLite。没有可安全修改的项目也可正常结束。
- 应用与恢复都自动备份当前材料，历史列表展示最近 20 次，支持恢复操作前版本。维护只影响后续翻译使用的材料，不修改已有译文。

建议先去重，再按需压缩角色说明、术语备注和规则；不需要每话都压缩，也不自动循环压缩，避免反复总结损失细节。

## 存储与并发

SQLite schema v7 新增 `translation_maintenance_previews` 和 `translation_brief_revisions`，启动时自动建表。预览保留 7 天（新建预览时清理），历史备份不自动删除，永久删除作品时一并清理。

预览以材料 JSON 的 SHA-256 版本为基线。应用时事务检查版本，若期间翻译或其他操作更新材料，拒绝覆盖并要求重新生成。维护与初始化、章节翻译共用单书任务锁。恢复也检查当前版本并先备份。

接口均继承现有鉴权：

- `GET /library/:site/:id/translation/maintenance`
- `POST /library/:site/:id/translation/maintenance/preview`（NDJSON）
- `POST /library/:site/:id/translation/maintenance/apply`
- `POST /library/:site/:id/translation/maintenance/restore`

维护沿用现有模型调用、思考等级、失败重试和 JSON 修复。校验主要保护结构、修改范围及固定标识，不对引用文本或来源章节做事实强匹配。模型对事实的总结仍需通过修改前后预览检查。

## 离线验证

`npm --prefix backend run test:maintenance` 使用临时 SQLite 和本地模拟 SSE 模型服务，覆盖名称检测、重复 create 隔离、AI 输出范围保护、压缩约束、预览应用、备份恢复、版本冲突和 HTTP 流式协议，不调用付费模型。

上线需同时部署前端构建与新版后端；本地修改不等于线上部署。后端启动时会执行数据库迁移，建议部署前备份数据库并等待在途翻译结束。
